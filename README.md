# Жол-ID Карго — единое окно для грузовых перевозок

Прототип грузового модуля платформы **«Жол-ID»** из проекта «Цифровая трансформация транспорта»
(Плахотный Артем, ИС-23-2р, Университет ALT, 2026).

Стек: **Python + FastAPI** (бэкенд, SQLite), **HTML + CSS + JavaScript** без фреймворков (фронтенд).

## Запуск

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn backend.app.main:app --reload --port 8765
```

После этого откройте http://localhost:8765. Документация API (Swagger) доступна на http://localhost:8765/docs.

При первом запуске создаются база `backend/zhol.db` и демо-данные: по одному аккаунту на каждую роль
и три перевозки на разных стадиях. Чтобы начать демонстрацию с чистого листа, остановите сервер,
удалите `backend/zhol.db` и папку `backend/uploads`, затем запустите сервер снова.

## Публикация в интернете (Render)

В корне лежит `render.yaml`: по нему Render сам создаёт веб-сервис (бесплатный тариф).
На Render нажмите **New → Blueprint**, выберите этот репозиторий и подтвердите создание.
Через несколько минут сайт будет доступен по адресу вида `https://zhol-id-cargo.onrender.com`.

Особенности бесплатного тарифа:
- после 15 минут без посетителей сервис засыпает, и первое открытие занимает около минуты;
- диск не сохраняется между перезапусками, поэтому база каждый раз создаётся заново с демо-данными.
  Для показа это удобно: у каждого гостя чистое демо.

Настройки через переменные окружения:

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `ZHOL_SIM_SPEED` | `0.5` | Сколько модельных часов проходит за 1 реальную секунду |
| `ZHOL_DEMO` | `1` | `0` отключает кнопки демо-входа |
| `ZHOL_DB`, `ZHOL_UPLOADS` | `backend/zhol.db`, `backend/uploads` | Где хранить базу и файлы |

## Роли

При регистрации пользователь выбирает, от чьего лица он работает:

| Роль | Что может |
|---|---|
| Грузоотправитель | Регистрирует перевозку, загружает документы, подаёт электронную декларацию, отправляет груз |
| Грузополучатель | Присоединяется по номеру, отслеживает груз, загружает контракт и свои документы |
| Экспедитор | Регистрирует перевозку за клиента, загружает документы, подаёт декларацию |
| Перевозчик | Присоединяется по номеру, загружает транспортную накладную, отправляет груз в путь |
| Таможня | Видит все перевозки, проверяет декларации, выпускает или отклоняет их с комментарием |

На экране входа есть кнопки **демо-входа** для каждой роли, чтобы на защите можно было быстро переключаться.

## Сценарий для демонстрации

1. **Расчёт стоимости.** Выберите вид транспорта, затем оборудование (контейнер, вагон, цистерна, рефрижератор…)
   и количество единиц. Допустимые масса и объём равны вместимости одной единицы, умноженной на количество
   (3 × 20′ = до 72 т и 99 м³). Больше ввести нельзя: поле подсвечивается, расчёт не выполняется,
   а при выходе из поля значение срезается до максимума. Сервер проверяет то же самое.
   Процент страховки и стоимость услуг (погрузка, сопровождение, экспедирование) вы указываете сами.
   Пустое поле означает ориентир по типовому тарифу. Кнопка «Оформить перевозку» переносит параметры в форму регистрации.
2. **Регистрация перевозки.** Перевозка получает номер вида `ZH-2026-7KQ4XM` и сохраняет стоимость.
   Экспедитор указывает своё вознаграждение. Он видит полную разбивку, а грузоотправитель,
   получатель, перевозчик и таможня видят одну сумму: «Общий фрахт (все услуги включены)».
3. **Отслеживание.** По номеру перевозку находит любой зарегистрированный пользователь, а без входа видна
   краткая информация. Перевозчик, получатель или экспедитор присоединяется к перевозке в своей роли.
4. **Документы.** Каждый участник загружает свои файлы (PDF, JPG, PNG, DOC(X), XLS(X), TXT, до 10 МБ).
   Платформа показывает, каких обязательных документов не хватает. Набор зависит от типа груза:
   для сельхозпродукции нужен фитосертификат, для опасного груза — MSDS.
5. **Электронная декларация.** Когда документы собраны, отправитель или экспедитор одной кнопкой формирует ЭД:
   данные перевозки и список файлов с хэшами SHA-256. Таможня выпускает или отклоняет её.
6. **Эффект ЭД на перевозку.** Без выпущенной декларации груз **останавливается** на таможенном узле
   (Хоргос, Достык, порт Актау), и на карте он отмечен красным. После выпуска сведения автоматически
   уходят во все органы, и груз едет дальше.
7. **Реестр.** Все события записываются в цепочку блоков. Браузер сам пересчитывает хэши, а кнопка
   «Подменить запись» показывает, как обнаруживается подделка.

## Структура

```
backend/app/
  main.py          приложение FastAPI, раздача фронтенда, ошибки валидации на русском
  data.py          справочники: роли, узлы коридора, маршруты, транспорт и тарифы, документы
  db.py            SQLite: схема и транзакции
  security.py      пароли (PBKDF2), сессии по токену
  services.py      бизнес-логика: перевозки, участники, документы, декларации, права доступа
  sim.py           модель движения груза и остановка на таможне без выпущенной ЭД
  calc.py          расчёт стоимости
  ledger.py        реестр событий (цепочка хэшей)
  seed.py          демо-аккаунты и демо-перевозки
  routers/         HTTP-эндпоинты: auth, meta + calc, shipments, ledger
frontend/
  index.html, css/styles.css
  js/app.js            запуск, вкладки, мониторинг, отслеживание, эффект
  js/auth.js           вход и регистрация с выбором роли
  js/shipment-view.js  карточка перевозки: участники, документы, декларация, маршрут
  js/calc.js           калькулятор стоимости
  js/new-shipment.js   регистрация перевозки
  js/declarations.js   очередь деклараций и печатная форма ЭД
  js/ledger.js         проверка реестра в браузере
  js/map.js, api.js, util.js, sha256.js
```

## Допущения прототипа

- Тарифы, сроки в пути и простои — модельные оценки, а не прайс перевозчиков и не официальная статистика.
  Курс в калькуляторе условный (510 ₸/$).
- Интеграции с КТЖ, «Астана-1», портом и странами-партнёрами смоделированы: «рассылка сведений»
  записывается в реестр.
- Компании в демо-данных вымышлены.
- Реестр хранится в одной базе. В реальной системе его копии были бы у каждого участника.
